# 홈 화면 위젯

앱을 열지 않아도 홈 화면에서 지금 스트릭이 며칠인지, 오늘 대화를 했는지 보여준다. 화면은 iOS·안드로이드가 각자 그리지만 **무엇을 보여줄지 정하는 규칙은 한 곳**에 있다.

## 어디에 무엇이 있나

| 위치              | 파일                                         | 역할                                                  |
| ----------------- | -------------------------------------------- | ----------------------------------------------------- |
| `packages/bridge` | `src/messages.ts`                            | `WidgetData` 규격과 `SYNC_WIDGET_DATA` 메시지         |
| `apps/web`        | `features/widget/model/build-widget-data.ts` | 서버 응답 세 개를 위젯 값 하나로 조립                 |
| `apps/web`        | `features/widget/ui/WidgetDataSync.tsx`      | 값이 바뀌면 셸로 보낸다 (루트 레이아웃에 상주)        |
| `apps/mobile`     | `widgets/widget-state.ts`                    | **어떤 그림을 보여줄지 정하는 규칙 (양 플랫폼 공용)** |
| `apps/mobile`     | `widgets/widget-store.ts`                    | 받은 값을 기기에 저장·복원                            |
| `apps/mobile`     | `widgets/widget-timeline.ts`                 | iOS용 — 앞으로의 전환 시각 목록을 만든다              |
| `apps/mobile`     | `widgets/StreakWidget.tsx`                   | iOS 화면                                              |
| `apps/mobile`     | `widgets/android/StreakAndroidWidget.tsx`    | 안드로이드 화면                                       |
| `apps/mobile`     | `widgets/sync/{ios,android}.ts`              | 플랫폼별 갱신 방식                                    |

## 값이 흐르는 길

```
백엔드 ──조회──▶ 웹 ──postMessage──▶ 셸 ──저장──▶ 기기 ──읽기──▶ 위젯
```

웹이 값을 만드는 이유는 서버와 통신하고 로그인 상태를 아는 쪽이 웹이기 때문이다. 위젯은 반대로 앱 안에서만 살아서 서버를 부를 수 없다.

넘기는 값은 여섯 가지뿐이다.

```ts
{
  (streak, todayDone, lastCompletedDate, todayCardTitle, weeklyDone);
}
```

**"지금 어떤 그림"은 값에 담지 않는다.** 앱이 꺼져 있어도 시간이 지나면 화면이 바뀌어야 하므로, 판단은 위젯 쪽이 현재 시각으로 직접 한다.

## 언제 갱신되나

| 시점                 | 무슨 일이 일어나나                                           |
| -------------------- | ------------------------------------------------------------ |
| **앱을 켤 때**       | 셸이 저장된 값을 읽어 위젯을 되살린다 (`syncWidgetOnLaunch`) |
| **로그인 직후**      | 웹이 스트릭·오늘 카드·달력을 받아 조립한 값을 보낸다         |
| **대화를 마쳤을 때** | 스트릭 캐시가 새로 받아지고, 값이 달라졌으므로 다시 보낸다   |
| **로그아웃**         | 빈 값을 보낸다 — 안 보내면 다음 사람 홈에 이전 기록이 남는다 |
| **시간이 흐를 때**   | 플랫폼마다 다르다 (아래)                                     |

웹은 **값이 실제로 달라졌을 때만** 보낸다. 직렬화한 문자열을 effect 키로 써서 같은 값을 반복 전송하지 않는다.

셸은 **저장을 끝낸 뒤에** 위젯을 갱신한다. 순서가 반대면 저장이 실패했을 때 위젯만 새 값을 들고 있게 되고, 다음 실행이 낡은 값으로 되돌려 놓는다.

## 안드로이드 동작 방식

**그때그때 다시 그린다.** 미래 시각을 예약하는 수단이 없다.

| 계기                | 경로                                                         |
| ------------------- | ------------------------------------------------------------ |
| 앱 실행 / 대화 완료 | `requestWidgetUpdate`로 등록된 위젯 3종을 즉시 다시 그린다   |
| 30분마다            | 시스템이 `widgetTaskHandler`를 부른다 (`updatePeriodMillis`) |
| 위젯을 홈에 추가    | 같은 핸들러가 불린다                                         |

30분은 안드로이드가 허용하는 최소 주기다. 그래서 **시간이 흘러 화면이 바뀌어야 하는 순간이 최대 30분까지 밀린다.** 매번 30분은 아니고 주기가 어디서 시작됐느냐에 달렸지만, 자정도 예외가 아니다.

특히 자정은 하루가 리셋되는 지점이라 밀리면 어색하다 — 새 카드가 왔는데 어젯밤 재촉 화면이 남는다. 앱을 열면 그 순간 정확해지므로 지금은 이대로 두지만, 실사용에서 거슬리면 `ACTION_DATE_CHANGED` 브로드캐스트를 받는 리시버를 붙이면 된다. 시스템이 자정에 보내는 신호라 **권한이 늘지 않는다** (정확 알람은 쓸 수 없다 — 아래 참고).

밀림이 틀린 정보가 되는 것들은 `capturedOn`으로 따로 막았다(위 "값이 흐르는 길" 참고). 30분 밀림이 남는 건 화면 전환 시각뿐이다.

정확 알람은 두 권한 다 우리에겐 맞지 않는다.

- `USE_EXACT_ALARM` — Play 정책상 알람시계·타이머·캘린더처럼 **정확한 시각이 앱의 핵심 기능**인 경우만 허용된다
- `SCHEDULE_EXACT_ALARM` — Android 14부터 기본 거부라 사용자가 설정에서 직접 켜야 동작한다

크기별로 위젯을 3개 등록한다(2×2·4×2·4×4). iOS와 달리 한 위젯이 여러 크기를 가질 수 없다.

**그림 파일은 앱 안에서 바로 읽는다.** iOS에서 필요한 공유 폴더 복사가 없다.

두 가지 함정이 있다.

- 화면 파일 맨 위의 `'use no memo'` — React Compiler가 손대면 위젯 변환기가 거부해서 **위젯이 아예 안 그려진다**
- 런처 칸은 정사각형이 아니다. 갤럭시 홈은 2×2도 세로가 길어서, 칸을 꽉 채우면 그림이 잘린다. `fitCard`가 칸 안에 들어가는 최대 카드를 계산한다

## iOS 동작 방식

**미리 예약해둔다.** 위젯은 원할 때 다시 그릴 수 없다.

앱이 켜지거나 값이 바뀌면 앞으로 **31일치** 전환 시각을 계산해 시스템에 넘긴다. 그 뒤로는 앱이 꺼져 있어도 예약한 시각마다 시스템이 알아서 화면을 바꾼다.

예약을 한 달치 넣는 이유가 있다. 예약이 바닥나면 **그 자리에서 화면이 멈춘다.** 3일치만 넣으면 앱을 안 여는 사람일수록 '타버림'에 옛 스트릭 숫자가 박힌 채 굳는다. 한 달치면 소등까지 흘러간다.

항목 수가 늘지는 않는다. 같은 화면이 이어지는 구간은 예약을 접어서, 스트릭이 살아 있으면 14개·끊겼으면 3개 정도다.

**그림은 공유 폴더로 한 번 복사한다.** 위젯은 앱과 별개로 도는 프로그램이라 앱 번들 안의 파일을 읽지 못한다. 앱 첫 실행 때 App Group 폴더로 복사하고, 버전 마커로 재복사를 막는다. 그림을 교체할 땐 `WIDGET_ART_VERSION`을 올린다.

**위젯 갤러리 미리보기도 실제 렌더다.** iOS에는 미리보기 이미지를 등록하는 API가 없다. 저장된 타임라인의 첫 항목을 그려 보여주고, 저장된 게 없으면(설치 직후) 안내 화면이 나온다.

화면 파일(`StreakWidget.tsx`)은 특이하게 동작한다. 함수를 통째로 **소스 문자열로 만들어** 위젯 쪽에 넘기고 위젯이 그걸 실행한다. 그래서 **함수 바깥 값은 위젯 쪽에 존재하지 않는다** — 색상표 같은 상수도 함수 안에 둬야 한다. 그 탓에 팔레트가 공용 파일과 이 파일 양쪽에 중복되고, 테스트가 두 값이 같은지 검사한다.

## 어떤 그림을 보여줄지

판정은 `widget-state.ts` 한 곳에서 하고 양 플랫폼이 같은 결과를 쓴다.

```
완료 이력도 오늘 카드도 없음  →  시작 안내 (로그인 전)
오늘 완료함                   →  축하 (7·14·20·30일은 마일스톤)
어제까지 완료 / 오늘은 아직    →  시간표 — 낮엔 여유, 밤이 깊을수록 재촉
이틀째                        →  타버림 (직전 스트릭을 그대로 보여준다)
3~6일                         →  해골 (0)
일주일~                       →  램프 균열
한 달~                        →  소등
```

**판정 기준은 `todayDone`이 아니라 마지막 완료 날짜다.** 위젯은 앱이 꺼져 있어도 혼자 다시 그려져서 저장된 값이 어제 것일 수 있다. 플래그를 믿으면 자정이 지나도 "오늘 완료!"가 남는다. 날짜끼리 비교하면 값이 낡아도 항상 맞다.

**날짜는 전부 서울 기준이다.** 서버 기준을 쓰는 게 원칙이지만 위젯은 서버를 부를 수 없어 여기서만 예외다.

## 알아둘 것

- `lastCompletedDate`는 서버에 없어서 프론트가 유도한다. 스트릭이 살아 있으면 어제, 끊겼으면 달력 네 개(주간 2 + 월간 2)를 뒤진다. 못 찾으면 조회 범위의 하루 전을 쓴다 — 정확한 날짜는 몰라도 "적어도 이만큼 쉬었다"는 사실이라 몰락 단계를 과장하지 않는다. **서버가 이 필드를 내려주면 이 유도 로직은 통째로 지울 수 있다**
- 위젯을 탭하면 앱만 열린다. 경로는 나르지 않는다 (알림과 다른 점)
- 위젯이 새로 붙는 앱 업데이트는 **버전을 올려야 한다**. `runtimeVersion`이 `appVersion`이라, 안 올리면 이 JS가 무선 업데이트로 옛 앱에 내려가 안드로이드에서 부팅이 실패한다
