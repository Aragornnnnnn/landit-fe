# 캐릭터 애니메이션 방식

대화 화면의 상대 캐릭터를 움직이기 위해 어떤 방식을 검토했고 무엇을 골랐는지 남긴다. 입모양·립싱크는 [character-lipsync.md](character-lipsync.md)에서 따로 다룬다.

## 요구

- 정적 이미지였던 캐릭터가 대화 상태(말하기·듣기·생각)에 반응해야 한다
- 가만히 있을 때도 살아 있어야 한다 — 호흡, 눈 깜빡임
- 속마음 타입(GOOD/NORMAL/BAD)에 맞는 표정이 필요하다
- WebView 셸 안에서 돌아야 하고, 저사양 기기에서도 견뎌야 한다

## 검토한 방식

| 방식                      | 상태 제어        | 형태 변형               | 외부 툴            | 판단     |
| ------------------------- | ---------------- | ----------------------- | ------------------ | -------- |
| SVG 파츠 분리 + CSS/WAAPI | 코드로 자유롭게  | 불가 (이동·회전·크기만) | 없음               | **채택** |
| Rive                      | 스테이트 머신    | 가능 (정점 보간)        | 에디터 필수        | 보류     |
| Lottie                    | 약함 (주로 재생) | 가능                    | After Effects 필수 | 제외     |
| 스프라이트 시트           | 조합 불가        | 그린 만큼만             | 없음               | 제외     |
| 투명 배경 비디오          | 불가             | 그린 만큼만             | 편집 툴            | 제외     |

### Rive — 검증했고, 지금은 보류다

가장 먼저 검토했고 런타임을 실제로 붙여 동작까지 확인했다. 공식 데모 파일을 재생하고 스테이트 머신 입력을 코드에서 발동시키는 것까지 문제없이 됐다. PoC 저장소 이름이 `rive-poc`인 것은 이 때문이다.

**장점이 분명하다.**

- **정점 보간** — 패스의 점 자체를 움직일 수 있다. 웃는 입을 찡그린 입으로 *변형*할 수 있고, 발음별 입모양도 진짜로 만들 수 있다
- **본 리깅** — 팔이 어깨·팔꿈치 관절로 자연스럽게 꺾인다
- **상태 블렌딩** — 상태 전환이 엔진 차원에서 섞인다
- **디자이너가 직접 수정** — 모션 변경에 개발자가 필요 없다. `.riv` 파일만 교체하면 된다

**그럼에도 미룬 이유는 이렇다.**

핵심은 **애니메이션을 코드로 만들 수 없다는 점**이다. Rive는 에디터에서 리깅하고 키프레임을 잡아 `.riv`로 내보내야 하며, 코드는 그 결과물을 재생·제어만 한다. 즉 캐릭터가 움직이려면 먼저 사람이 에디터에서 며칠을 써야 한다(툴 습득 반나절, 리깅 반나절~~하루, 상태별 애니메이션 각 1~~3시간, 스테이트 머신 배선 한두 시간).

부수적으로 `.riv`는 바이너리라 코드 리뷰에서 변경 내용을 볼 수 없고, 런타임 의존성이 추가된다.

**언제 다시 볼 것인가.** 형태 변형이 필요해지는 시점이다. 구체적으로는 발음별 입모양(비짐)을 제대로 만들어 발음 학습 기능으로 쓰려 할 때, 또는 캐릭터 동작이 전신 제스처 수준으로 복잡해질 때다. 그때는 지금 만든 파츠 분리 SVG가 그대로 에디터 임포트 소재가 되므로 작업이 헛되지 않는다.

### Lottie, 스프라이트, 비디오

**Lottie**는 After Effects 결과물을 재생하는 데는 좋지만 상태를 세밀하게 제어하기 어렵다. "말하는 중에 눈만 깜빡이고 눈썹만 올리기" 같은 조합이 우리 요구인데, Lottie는 미리 만든 구간 재생에 가깝다. 툴 의존은 Rive와 같으면서 제어력은 더 약하다.

**스프라이트 시트와 비디오**는 상태 조합에서 탈락한다. 상태 6개 × 표정 변화 × 말하기 여부를 미리 그려두면 경우의 수가 폭발하고, 파일 크기도 감당이 안 된다.

### SVG 파츠 분리 — 채택

SVG는 이미지가 아니라 DOM이다. `<path>` 하나하나가 선택 가능하고 CSS·JS가 닿는다. 그래서 조각을 그룹으로 묶어 놓기만 하면 브라우저 기본 기능으로 움직일 수 있다.

- 외부 툴·라이브러리가 필요 없다
- 모션이 텍스트라 코드 리뷰에서 변경이 보인다
- 상태 조합이 자유롭다 — 표정과 입이 다른 파츠라 동시에 성립한다
- 즉시 시작할 수 있다

한계는 **형태 변형이 안 된다**는 점이다. 조각을 이동·회전·확대만 할 수 있어서, 웃는 입을 작게 만들 수는 있어도 찡그린 입으로 바꿀 수는 없다. 이 경우에는 해당 표정의 벡터를 따로 그려 두고 교체한다.

## 파이프라인

피그마의 벡터화된 캐릭터를 파츠 SVG로 만드는 과정은 스크립트로 자동화되어 있다.

1. 피그마에서 벡터화 노드를 SVG로 내보낸다 (이름 없는 `<path>` 150여 개가 평평하게 나열된 상태)
2. 스크립트가 좌표와 노드 번호를 기준으로 파츠 그룹(`#head`, `#mouth`, `#eye-left` …)으로 재조립한다
3. 표정 교체용 수제 벡터(눈웃음 아크, 찡그린 입)를 해당 그룹 뒤에 삽입한다
4. 캐릭터별 개별 보정을 굽는다 (예: 원본 입이 기울어 있으면 반대 회전을 그룹에 넣어 수평화)

**캐릭터가 늘어나도 모션 코드는 그대로다.** 모든 캐릭터가 같은 그룹 이름 규약을 쓰기 때문이다. 새 캐릭터는 스크립트에 설정 블록(슬라이스 정의, 수제 벡터 좌표·색, 개별 보정) 하나를 추가하면 된다.

## 움직임의 3겹 구조

한 파츠에 여러 움직임이 동시에 걸린다. 층을 나눠 서로 침범하지 않게 한다.

**1겹 — 상시 idle (CSS 무한 애니메이션)**

상태와 무관하게 항상 돈다. 호흡은 세로 1.4% 수준으로 아주 작게, 들숨이 날숨보다 길게 준다. 머리와 팔은 몸통보다 0.2~0.3초 늦게 따라온다(2차 모션). 호흡 4.2초와 체중 이동 7.6초처럼 주기를 어긋나게 두어 같은 자세가 반복되지 않게 한다.

**2겹 — 상태 포즈 (CSS 클래스)**

컨테이너에 상태 클래스가 붙으면 파츠들이 0.4초 오버슈트 이징으로 목표 자세로 이동한다.

**3겹 — 불규칙 액센트 (Web Animations API)**

깜빡임(1.8~5.5초 랜덤), 끄덕임, 눈썹 반응처럼 주기가 일정하면 어색해지는 것들은 JS가 랜덤 타이밍으로 일회성 애니메이션을 쏜다.

## 함정

**같은 엘리먼트에 CSS 애니메이션과 transform을 같이 걸면 하나가 죽는다.** 그래서 머리를 `#head`(호흡)와 `#head-inner`(포즈)로 중첩해 각자 자리를 준다.

**일회성 애니메이션은 현재 포즈를 덮어쓴다.** `composite: 'add'`를 붙여야 포즈 위에 더해진다. 없으면 끄덕이는 순간 기울인 고개가 0으로 리셋됐다 돌아오며 튄다.

**2D 정면 캐릭터에서 고개 끄덕임에 회전을 쓰면 갸우뚱으로 보인다.** 화면 평면 회전은 좌우 기울임이기 때문이다. 하강과 세로 압축을 조합한 원근 착시로 만들어야 한다.

**전역 `transform-box: fill-box`는 SVG에 구운 좌표 지정 회전과 충돌한다.** 구운 래퍼만 `transform-box: view-box`로 예외 처리한다.

## 정리

지금 방식은 **외부 툴 없이 코드만으로 상태 반응형 캐릭터를 만드는 것**이고, 대가로 형태 변형을 포기했다. 대화 상대로서 살아 있게 보이는 데는 충분하며, 발음 학습처럼 입 모양 자체가 콘텐츠가 되는 단계에서 Rive를 다시 검토한다.
