# 구독 결제 설계와 출시 순서

앱 1.3.0에 인앱 구독 결제를 넣는다. 결제 실행은 RevenueCat이, 유료 여부 판단은 BE가, 화면 분기는 웹이 맡는다.
심사는 1.3.0으로 받고, 실제 결제 오픈 시점은 웹 플래그 하나로 우리가 정한다.

이 문서는 2026-09-05 기준으로 정해진 것과 미정인 것을 한곳에 모은다. 이슈는 LAN-446~449 네 개이고 스택 PR로 순서대로 올린다 (맨 아래 절).

## 결정 요약

| 항목           | 결정                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| 상품           | 월간 `com.saynow.app.premium.monthly` ₩9,900, 연간 `com.saynow.app.premium.yearly` ₩59,900              |
| 월간 가격 성격 | 정가 19,800원의 출시 기념 50%. 지금 가입하면 매달 9,900원이 계속 유지된다 (인트로 오퍼가 아니라 기본가) |
| 연간 혜택      | 7일 무료 체험 후 연 59,900원. 월 4,990원꼴                                                              |
| 무료 구간      | 온보딩, 첫 대화 하나, 그 대화의 표현 학습 하나까지. 그다음 학습 진입부터 페이월                         |
| 페이월 UI      | 피그마 `paywall` 페이지 `★ 최종 레이아웃` 섹션 3장                                                      |
| 아이콘         | 혜택 목록은 기능별 라인 아이콘 (이모지 안 씀)                                                           |
| 버튼           | 앱 `Button` lg 3D 그대로                                                                                |
| 롤아웃         | 웹 먼저 배포(버전 게이트 ≥ 1.3.0 + 플래그) → 1.3.0 심사 → 승인 후 출시 → 오픈 날 플래그 ON              |

미정은 두 가지다. 월간 카드에 할인 표시를 남길지(결정 ①), 연간 카드 큰 숫자를 연 59,900원으로 쓸지 월 4,990원으로 쓸지(결정 ②). 둘 다 피그마 결정 섹션에 선택지가 나란히 있다.

## 상품과 가격

App Store Connect 구독 그룹 `premium` (ID 22358008, 표시명 "랜딧 프리미엄"). 2026-09-04 확인 기준 등록 상태는 아래와 같다.

| 구독    | 제품 ID                          | 기간  | 한국 가격 | 신규 구독 특가 | 판매 국가 | 심사 스크린샷 |
| ------- | -------------------------------- | ----- | --------- | -------------- | --------- | ------------- |
| Yearly  | `com.saynow.app.premium.yearly`  | 1년   | ₩59,900   | 없음           | 미설정    | 없음          |
| Monthly | `com.saynow.app.premium.monthly` | 1개월 | ₩9,900    | 없음           | 미설정    | 없음          |

두 구독 모두 "제출 준비 중"이고, 첫 자동 갱신 구독은 새 앱 버전(1.3.0)과 함께 제출해야 한다. 연간의 7일 무료 체험은 신규 구독 특가로 아직 등록되지 않았다. 등록 전에는 결제 시트에 체험이 뜨지 않으니 출시 전 체크리스트에 있다. Google Play 상품 등록 여부는 확인하지 못했다.

화면에 쓰는 숫자와 근거는 다음과 같다.

- 월간 정가 19,800원, 판매가 9,900원. 정가는 스토어 어디에도 없는 값이라 취소선으로 보여줄지가 결정 ①이다.
- 연간 59,900원. 정가 1년치 237,600원 대비 75% 할인, 월간 1년치 118,800원 대비 50% 저렴. 어느 기준으로 칩을 쓸지는 결정 ①의 선택지에 묶여 있다.
- 월 환산가는 59,900 ÷ 12 = 4,991원이라 "월 4,990원"으로 표기한다.
- 가격은 화면에 하드코딩하지 않는다. 결제 시트와 카드 가격은 `GET_OFFERINGS`로 받은 스토어 문자열을 쓰고, 정가·할인율 같은 표시용 숫자만 상수 한 곳에 둔다.

## 역할 분담

| 주체                | 하는 일                                                                           | 안 하는 일                 |
| ------------------- | --------------------------------------------------------------------------------- | -------------------------- |
| RevenueCat (셸 SDK) | 상품·가격 조회, 결제, 복원. 스토어 영수증 검증 후 BE로 웹훅 발송                  | 유료 여부 저장             |
| BE                  | 웹훅 받아 `user_profile`에 구독 상태 저장. `GET /api/v1/me/subscription`으로 제공 | 스토어와 직접 통신         |
| 셸 (`apps/mobile`)  | RevenueCat 호출을 브릿지로 노출. 로그인 시 `Purchases.logIn(userId)`              | 유료 여부 판단, 화면       |
| 웹 (`apps/web`)     | BE `premium` 값으로 페이월·잠금 분기. 결제 버튼은 브릿지로 셸 호출                | 가격 하드코딩, 영수증 처리 |

유료 상태를 아는 곳은 BE 하나다. 웹은 BE만 보고, 셸은 결제 동작만 한다.

## 무료 구간과 페이월 게이트

가치를 먼저 보여주고 구독을 요구한다. 구독이 없어도 아래까지는 막지 않는다.

1. 온보딩
2. 첫 대화 하나
3. 첫 대화 직후 "수준 파악 완료" 화면 (한 번만 뜬다, CTA는 표현 학습으로)
4. 그 대화의 표현 학습 하나

표현 학습 하나를 완료한 뒤부터 새 대화 시작, 다음 표현 학습, 스몰톡 진입이 페이월로 막힌다. 홈은 열람할 수 있다. 페이월을 닫으면 홈으로 가고, 학습에 다시 들어가면 페이월이 또 뜬다.

게이트는 학습 진입 지점에 건다 (`features/conversation`, `features/expression`, `features/small-talk`). `(protected)/layout.tsx`로 화면 전체를 막지 않는다.

"첫 대화 완료·첫 표현 완료"는 서버 값으로 판단해 기기를 바꿔도 같아야 한다. 시나리오 완료 상태와 표현 학습 진행도 필드를 확인하고 없으면 BE 이슈로 뺀다. 무료 체험 중(`periodType=TRIAL`)과 해지 예약(`CANCELED`, 만료 전)은 `premium=true`라 게이트에 걸리지 않는다.

전환 시점에 이미 대화와 표현을 여러 개 끝낸 기존 사용자는 즉시 게이트에 걸린다. 유예를 줄지는 미정.

## 페이월 노출 조건

세 조건이 전부 참일 때만 결제 UI를 보여준다.

1. `window.__LANDIT_NATIVE__.appVersion >= 1.3.0` — 1.2.x 셸에는 SDK도 브릿지 핸들러도 없다. 브라우저 단독 접속은 값이 없어서 자연히 안 뜬다. 웹에는 아직 버전 비교 유틸이 없다(앱 업데이트 판단은 서버가 `versionName`으로 한다). 게이트 이슈에서 semver 비교를 새로 만들고 테스트를 붙인다.
2. `NEXT_PUBLIC_PAYMENT_ENABLED` — 오픈 시점을 잡는 플래그. Vercel 환경변수라 바꾸면 재배포가 필요하다 (`NEXT_PUBLIC_`은 빌드 시점에 박힌다).
3. BE `premium`이 `false` — 이미 구독 중이면 안 보여준다.

이 세 조건은 페이월 노출뿐 아니라 위 절의 잠금 게이트에도 같이 걸린다. 1.2.x 유저는 결제를 못 하니 잠기면 안 된다.

버전 게이트만으로도 "누가 보느냐"는 제어된다. 플래그를 따로 두는 이유는 1.3.0 출시일과 결제 오픈일을 분리하고, BE 샌드박스 설정 전환(아래 절)과 시점을 맞추기 위해서다.

로그인 전에는 결제 버튼을 아예 보여주지 않는다. BE가 웹훅의 `app_user_id`를 숫자 유저 id로 풀기 때문에 익명 상태 결제는 매핑이 안 된다.

## 페이월 화면

피그마 파일 `3LwSPCntVV55PU1CIcXbVN`, `paywall` 페이지의 `★ 최종 레이아웃` 섹션. 프레임은 연간 선택 `2020:3`, 월간 선택 `2020:86`, 작은 폰 375×667 `2021:2`.

구성은 위에서부터 상태바, 닫기(좌)와 구매 복원(우), 로고+PREMIUM 배지, 단체샷 히어로, 혜택 6줄, 플랜 카드 2장, CTA, 하단 안내, 이용약관·개인정보 처리방침 링크다. 구매 복원 버튼과 약관 링크는 애플 심사 요구사항이다.

정해진 스타일은 다음과 같다.

- 선택 카드는 주황 2px 테두리와 `#FFFBF8` 배경. 체크 아이콘은 쓰지 않는다. 안 고른 카드는 흰 배경에 회색 1px.
- 연간이 기본 선택. 할인 칩(골드 그라데이션)은 연간 카드 상단 테두리에 절반 걸친다. 월간 카드에 할인 태그를 둘지는 결정 ①.
- 카드 안 순서는 제목, 취소선 정가, 큰 가격, 부제 한 줄.
- 혜택 아이콘은 라인 아이콘 (calendar, globe, sparkles, mic, chat, heart). `shared/ui/Icons.tsx`에 없는 것은 lucide path를 인라인으로 추가한다.
- 로고 줄은 원본의 1.25배(높이 37.5), PREMIUM 배지 글자 13px.
- CTA는 `Button` lg 56 · 3D. md 전환은 보류.
- 작은 폰(667pt)에서는 상태바 20, 상단 바 32, 혜택 글자 13px·아이콘 18px·줄 간격 4, 플랜 위 여백 12, CTA 아래 여백 8로 줄여 히어로 이미지를 자르지 않고 약관 링크까지 한 화면에 넣는다. 화면 높이 기준 분기로 구현한다.

문구는 다음과 같다.

| 위치           | 연간 선택 상태                                  | 월간 선택 상태                            |
| -------------- | ----------------------------------------------- | ----------------------------------------- |
| 월간 카드 태그 | 출시 기념 50% (결정 ①에 따라 없앨 수 있음)      | 같음                                      |
| 월간 카드 부제 | 지금 시작하면 계속 이 가격                      | 같음                                      |
| 연간 카드 부제 | 월 4,990원 · 7일 무료 체험                      | 같음                                      |
| CTA            | 7일 무료 체험 시작하기                          | 월 9,900원으로 시작하기                   |
| 하단 안내      | 7일 무료 체험 후 연 59,900원 · 언제든 해지 가능 | 매월 9,900원 자동 결제 · 언제든 해지 가능 |

혜택 6줄은 기획 원문 그대로다. 셋째 줄 "나에게 꼭 맞는 원어민 표현 추천"은 학습까지 포함하는 문구로 바꿀 예정이며 확정 전이다.

계측 이벤트는 페이월 노출, 플랜 선택, 구매 시작, 구매 성공, 구매 취소, 복원 탭.

## 심사와 출시 순서

앱이 웹뷰 셸이라 심사관은 라이브 웹(`www.landit.im`)을 본다. 그래서 웹이 먼저 배포돼 있어야 한다.

1. **웹 배포.** 결제 UI 포함, 버전 게이트 걸림, `NEXT_PUBLIC_PAYMENT_ENABLED=true`. 1.2.x 유저는 게이트 때문에 변화가 없다.
2. **BE 운영 설정 확인.** `apply-sandbox-events`가 `true`인지. (아래 샌드박스 절 참고)
3. **프로덕션 RevenueCat 프로젝트 준비.** 운영 웹훅 URL `https://api.landit.im/webhooks/revenuecat`과 Authorization 값 등록. IAP 상품은 1.3.0 빌드에 첨부해서 같이 제출한다 (첫 제출 시 필수). 애플 계정 이전이 진행 중이라 App Store 연결(공유 비밀, In-App Purchase 키)은 새 팀 기준으로 잡는다.
4. **1.3.0 심사 제출.** 심사관만 결제 UI를 보고 샌드박스로 결제한다. 심사관이 페이월까지 가려면 대화 하나와 표현 하나를 끝내야 하므로 심사 노트에 경로를 적거나, 그 상태를 이미 만든 테스트 계정을 준다.
5. **승인.** `NEXT_PUBLIC_PAYMENT_ENABLED=false`로 웹 재배포한 뒤 1.3.0을 출시한다. BE에 `apply-sandbox-events=false` 전환을 요청한다.
6. **결제 오픈.** 원하는 날 `NEXT_PUBLIC_PAYMENT_ENABLED=true`로 재배포. 앱 업데이트 없이 그 자리에서 열린다.

이후 결제 기능이 바뀌어 재심사를 받을 때는 5번 이전 상태(웹 플래그 true, BE 샌드박스 true)를 심사 기간에만 잠깐 복원한다.

## 샌드박스 이벤트

애플 심사팀과 TestFlight 테스터는 실제 카드가 아니라 샌드박스 계정으로 결제한다. 이 결제도 RevenueCat 웹훅으로 BE에 오지만 `environment: SANDBOX`로 온다.

- BE PR [#166](https://github.com/Aragornnnnnn/landit-be/pull/166)은 SANDBOX를 구분 없이 반영한다.
- BE 이슈 [#165](https://github.com/Aragornnnnnn/landit-be/issues/165)는 운영에서 SANDBOX를 무시하는 설정값(`apply-sandbox-events`)을 추가한다. 출시 후 TestFlight 결제로 공짜 프리미엄이 되는 걸 막는 용도다.
- **심사 기간에는 운영도 `true`여야 한다.** `false`면 심사관이 결제해도 프리미엄이 안 켜져서 리젝 사유가 된다. 이슈 본문의 "prod는 false"는 출시 이후 상태다.

## BE 계약

`GET /api/v1/me/subscription`

| 필드                 | 값                                                              | 웹에서 쓰는 곳          |
| -------------------- | --------------------------------------------------------------- | ----------------------- |
| `premium`            | `boolean`                                                       | 잠금·페이월 분기 (유일) |
| `subscriptionStatus` | `NONE` / `ACTIVE` / `CANCELED` / `EXPIRED`                      | 배지 표시               |
| `periodType`         | `TRIAL` / `INTRO` / `NORMAL` / `PROMOTIONAL` / `PREPAID` / null | 무료 체험 표시          |
| `expiresAt`          | `LocalDateTime` / null                                          | 만료일·다음 결제일 표시 |

`CANCELED`는 해지 예약 상태로 만료 전까지 `premium=true`다. 잠금 판단은 반드시 `premium`만 본다.

웹훅은 BE가 처리하므로 웹·셸은 관여하지 않는다. `app_user_id`는 우리 유저 id를 문자열로 넘긴 값이어야 한다.

게이트에 필요한 "첫 대화 완료·첫 표현 완료" 값은 이 응답에 없다. 기존 시나리오·표현 API의 완료 필드를 쓰거나 BE에 요청한다.

## 브릿지 메시지

`packages/bridge`에 추가한다. 이름은 구현 시 확정. 스키마는 `packages/bridge/src/messages.ts`(zod), 버전 상수는 `nativeContext.ts`의 `NATIVE_BRIDGE_VERSION`(현재 2)을 올린다. 왕복 선례는 `GET_NOTIFICATION_PERMISSION` → `NOTIFICATION_PERMISSION`.

웹 → 셸

| 메시지                         | 페이로드                     | 동작                                            |
| ------------------------------ | ---------------------------- | ----------------------------------------------- |
| `IDENTIFY`                     | `{ userId: string \| null }` | `Purchases.logIn(userId)` / null이면 `logOut()` |
| `GET_OFFERINGS`                | 없음                         | 현재 오퍼링의 패키지 목록 조회                  |
| `PURCHASE`                     | `{ packageId }`              | 해당 패키지 결제                                |
| `RESTORE_PURCHASES`            | 없음                         | 구매 복원                                       |
| `OPEN_SUBSCRIPTION_MANAGEMENT` | 없음                         | 스토어 구독 관리 화면 열기 (마이페이지용)       |

셸 → 웹

| 메시지            | 페이로드                                                    |
| ----------------- | ----------------------------------------------------------- |
| `OFFERINGS`       | `{ packages: [{ id, priceString, period }] }`               |
| `PURCHASE_RESULT` | `{ status: 'success' \| 'cancelled' \| 'error', message? }` |
| `RESTORE_RESULT`  | `{ status: 'success' \| 'error', message? }`                |

`priceString`은 스토어가 주는 로컬라이즈된 문자열을 그대로 쓴다. 웹은 가격을 하드코딩하지 않는다. 결제 메시지를 모르는 구버전 셸에서는 웹이 앱 업데이트 안내로 빠진다.

## 웹 결제 흐름

1. 페이월 진입 시 `GET_OFFERINGS`로 가격을 받아 채운다.
2. 구매 버튼 → `PURCHASE`. 복원 버튼 → `RESTORE_PURCHASES`.
3. `success`를 받으면 구독 쿼리를 invalidate하고 최대 10초쯤 짧게 폴링한다. 웹훅이 BE에 닿기까지 몇 초 지연이 있어 한 번 refetch로는 아직 `premium=false`일 수 있다. 그동안은 로딩 상태.
4. `premium=true`가 되면 페이월을 닫고 원래 가려던 화면으로 이어진다.

페이월 화면 쪽에서는 CTA가 `requestPurchase(plan)` 하나만 부른다. LAN-446에서는 이 함수가 비어 있고, LAN-447에서 브릿지 왕복으로 채운다.

## 마이페이지와 법적 문서

마이페이지(`(protected)/me`)에 플랜 이름, 상태(체험 중·구독 중·해지 예정), 다음 결제일, 구독 관리 진입, 환불 안내를 둔다. 구독 관리는 셸이 `OPEN_SUBSCRIPTION_MANAGEMENT`로 스토어 화면을 연다. 환불은 앱에서 처리하지 않고 애플은 `reportaproblem.apple.com`, 구글은 Play 환불 요청으로 안내한다. 구독 없는 사용자에게는 이 영역 대신 페이월 진입 버튼을 보여준다.

이용약관에는 구독 상품·가격 고지·자동 갱신·무료 체험 종료 시 과금·해지 방법·환불 기준 조항이, 개인정보 처리방침에는 결제 처리 위탁(애플·구글·RevenueCat)과 수집 항목이 들어가야 한다. 문서는 `(public)/(legal)/terms`, `privacy`. 문안은 팀에서 확정한 텍스트를 받아 넣고 시행일을 갱신한다. 심사 제출 전에 반영돼야 한다.

## 미정

- 결정 ①. 월간 카드에 "출시 기념 50%" 태그와 19,800 취소선을 둘지(A 강조 없음 / B 할인 표시 + 연간 75% / C 할인 표시 + 연간 "월간보다 50% 저렴").
