# 발음 평가 단어별 재생 오류 분석을 위한 진단 정보 추가

## 목적과 범위

iPhone에서 `went`의 내 발음 재생이 `camping~with` 구간과 일치하는 현상을 조사한다.
서버 응답, 화면에서 선택한 단어와 재생 요청, 미디어 이벤트의 위치를 같은 평가 회차로 연결한다.
기존 정렬·seek·종료 동작을 변경하지 않고 관측 정보만 추가한다.

## 구현

- 기존 ADMIN 계정만 평가 성공 시 메모리에 진단 회차를 만들고 결과 하단의 `발음 재생 진단`을 본다.
- 서버 응답의 단어 순서·텍스트·시작/종료 시간을 즉시 복사해 보존한다.
- 전체 내 발음과 단어의 재생이 시작될 때 기록을 열고, 요청 구간과 `loadedmetadata`, `seek-requested`, `seek-assigned`, `seeked`, `playing`, `timeupdate`, `segment-stop`, 완료/교체/화면 종료 이벤트를 남긴다. 중단 버튼을 눌렀을 때는 진행 중인 기록을 닫는다.
- 위치·길이·배속·seek 가능 범위·재생 상태·문서 가시성·프레임 간격을 저장한다. 이벤트의 경과 시간과 재생 시작 UTC 시각을 함께 제공한다.
- 최근 8회, 회차당 최대 160개 이벤트만 보존한다. 초과 시 시작 8개와 최근 이벤트를 유지하고 버린 개수를 표시한다.
- 공유 버튼을 누른 순간 JSON을 생성한다. 기존 네이티브 SHARE / Web Share / 클립보드 경로를 사용하고, 실패 시 선택 가능한 텍스트로 남긴다.
- 계정·기기 식별자, 토큰, 오디오 URL, 사용자 발화·녹음 바이트는 포함하지 않는다. 자동 외부 전송과 영구 저장은 없다.
- 새 평가 성공 시 보고서를 교체한다. 분석 실패로 이전 평가로 복귀하면 기존 녹음과 보고서를 유지한다.

## 재현과 판독

1. 이 변경이 반영된 웹 버전에서 ADMIN 계정으로 같은 표현을 다시 평가한다.
2. 화면 녹화를 켜고 전체 내 발음, 문제가 난 단어를 재생한다.
3. 화면을 떠나거나 다시 평가하기 전에 `발음 재생 진단` → `진단 정보 공유`를 누른다.
4. 화면 녹화와 JSON을 함께 비교한다. 앱/빌드 버전과 `LAN-844-v1` 스키마로 진단 활성화를 확인한다.

- `responseWords`와 해당 `order`의 `requestedSegment`가 다르면 앱 연결 경로를 조사한다.
- 요청과 `seeked`/`playing` 위치가 다르면 seek 경로를 조사한다.
- `segment-stop`/완료 위치가 요청 종료를 넘으면 프레임 간격과 문서 가시성을 함께 조사한다.
- 값은 맞는데 다른 소리가 나오면 같은 영상의 전체 내 발음과 파형을 대조한다. `currentTime`은 브라우저가 보고한 미디어 시간이며 실제 출력된 PCM의 증거가 아니다.
- 응답 구간 자체가 녹음의 단어와 어긋나면 서버 정렬을 조사한다. JSON만으로 실제 단어 경계나 단일 원인을 확정하지 않는다.
- 배포와 실제 iPhone 재현은 로컬 자동 검증과 별개의 단계다.

## 검증

- 응답 스냅샷 보존, 회차 격리, 기록 상한, seek 이벤트, 콜백 실패 격리, 자동재생 거부, 프레임 지연, 리스너 해제를 테스트한다.
- 관리자 노출, 공유 시점의 최신 보고서, 공유 실패 시 수동 복사를 테스트한다.
- 표현 학습 테스트: 25개 파일, 191개 테스트 통과. 같은 단어의 재생·중단·재시작이 한 렌더 사이에 일어나는 경우도 검증했다.
- 웹 TypeScript, 변경 파일 ESLint·Prettier, `git diff --check` 통과.
- 프로덕션 `next build` 통과. 샌드박스 내 compile 정체로 중단 후 제한을 해제해 재실행했다.
- pnpm은 저장소 지정 버전 10.14.0을 사용했다. 로컬 Node 26의 전역 localStorage 충돌을 피하도록 테스트 실행 시 `NODE_OPTIONS=--no-experimental-webstorage`를 적용했다.
- 수정한 진단 모듈·재생 훅을 데스크톱 WebKit(iPhone 15 프로필) 임시 페이지에서 실행했다. 정상 요청 1200–1400ms에서 시작 1200ms·종료 1410ms를 기록했고, 인위적인 400ms 지연에서는 종료 이벤트의 `sinceLastFrameMs=409`를 기록했다. React 배선은 임시 대역이며 실제 iPhone 앱 검증은 아니다.
- CI, 운영 배포, 실제 iPhone에서의 보고서 공유·원인 확정은 미실행이다.
