대화 상대의 목소리는 어디서 오나

목소리(ttsVoice)와 말할 문장은 백엔드 응답에 실려 온다. 미리 만든 mp3가 있으면 그대로 틀고, 없으면 웹 서버 /api/tts가 Deepgram에 직접 합성을 맡긴다.

시나리오

정해진 질문은 미리 만든 mp3, 그때그때 달라지는 맞장구만 Deepgram
① 첫 질문
화면에 들어오자마자 상대가 먼저 묻는다. 합성 없이 mp3를 바로 튼다.
백엔드 응답
GET /scenarios/daily
openingPreview
├ character.ttsVoice ← 목소리
└ questionAudioUrl ← 첫 질문 mp3
브라우저
mp3 주소로 바로 재생
합성 없이 바로
소리 출처
CDN mp3
백엔드가 미리 만든 질문 음원
Deepgrammp3 주소가 비어 있거나 재생에 실패하면 첫 질문 문장(aiOpeningMessage) 전체를 Deepgram으로 합성한다.
② 내가 말한 뒤 — 맞장구 + 다음 질문
짧은 맞장구만 Deepgram으로 만들고, 끝나면 정해진 다음 질문 mp3를 이어 튼다.

소리 출처

미리 만든 다음 질문 음원
Deepgram마지막 인사처럼 정해진 질문이 없는 발화는 ttsText·questionAudioUrl이 비어 온다. 이때는 나누지 않고 content 전체를 Deepgram으로 합성한다.
mp3 실패질문 mp3 재생에 실패하면 대신 합성하지 않고 그 발화를 끝낸다. 질문 글자는 화면에 그대로 남는다.

스몰톡

매번 다른 대화라 미리 만든 음원 없이, 상대가 하는 말은 전부 Deepgram
⓪ 홈 자기소개
상대를 고를 때 나오는 인사. 문구가 고정이라 웹에 넣어 둔 mp3를 튼다. 백엔드 응답은 쓰지 않는다.
백엔드 응답
없음. 문구·음원·목소리 모두 웹 고정값
브라우저
웹에 든 mp3 재생
합성 없이 바로
소리 출처
웹 정적 파일
/audio/smalltalk-intro-*.mp3
Deepgrammp3 재생에 실패하면 자기소개 문장을 웹에 적힌 목소리(partner.ts)로 Deepgram 합성한다.
① 첫 마디
고른 상대로 대화를 열면, 상대가 먼저 건네는 첫 마디를 통째로 Deepgram으로 만든다.
백엔드 응답
POST /free-talk/sessions
요청 characterId (고른 상대)
├ character.ttsVoice ← 목소리
└ currentMessage.content ← 첫 마디
브라우저
문장 전체 합성 요청
input = content
웹 서버 · 키 보관
/api/tts
시나리오와 같은 경로
소리 출처
Deepgram
POST /v1/speak → mp3
② 내가 말한 뒤 — 상대의 다음 말
반응과 질문이 한 문장으로 오므로 통째로 Deepgram으로 만든다. 응답을 받자마자 미리 합성해 둔다.
백엔드 응답
POST /free-talk/sessions/{id}/messages
nextMessage.content ← 다음 말 전체
브라우저
문장 전체 합성 요청
input = content
웹 서버 · 키 보관
/api/tts
시나리오와 같은 경로
소리 출처
Deepgram
POST /v1/speak → mp3
Deepgram내가 작별 인사를 하면 종료 확인(/exit-decision)을 보내고, 그 응답의 nextMessage.content(상대의 마무리 인사)도 같은 길로 합성한다.

모든 단계 공통

부르지 않음ttsVoice가 null로 오면 합성하지 않고, 말하는 시간만큼 기다린 뒤 대화를 잇는다.
부르지 않음다시 듣기는 방금 받은 소리를 그대로 다시 튼다.
키Deepgram TTS 키(DEEPGRAM_TTS_API_KEY)는 웹 서버에만 있다. 브라우저는 /api/tts만 부른다. STT 키와는 별개다.
